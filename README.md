# 挪车二维码

挡风玻璃上贴一张二维码：别人扫到后，点一下就能**一键拨号**联系车主。

同一套代码，两个运行目标：

| | Cloudflare Workers | Node.js |
|---|---|---|
| 数据 | D1（`src/d1.js`） | `node:sqlite`（`src/db.js`） |
| 入口 | `src/worker.js` | `src/server.js` |
| 依赖 | 无（不需要 `nodejs_compat`） | 无（Node 内置模块） |
| 适合 | 正式对外部署 | 本地跑、内网、自建服务器 |

路由、页面模板、二维码编码器全部共享（`src/app.js`、`src/views.js`、`src/qr.js`），
所以两个目标的行为一定一致，改一处两边都生效。

## 二维码怎么用（先看这个）

**域名根路径是车主入口**：输域名进去就是后台（没登录先去 `/login`）。
给陌生人扫码的地址都带路径：

| 用途 | 地址 |
| --- | --- |
| 车主后台（输域名即可） | `域名/` → `/login` → `/me` |
| 一车一码（推荐） | `域名/c/<编号>` |
| 通用码（一张贴纸贴所有车） | `域名/m` |
| 某辆车的管理链接（发给开车的人） | `域名/edit/<编号>.<签名>` |

> 早先版本把通用码放在根路径，结果是车主输域名进来看到的是给陌生人看的页面、
> 还找不到后台入口。已改掉；如果你印过指向根路径的贴纸，重印一次即可。

**一车一码**（`域名/c/<编号>`）—— 每辆车有自己的编号，**扫哪辆就显示哪辆**，扫码人不需要做任何选择。
想让扫码结果直接对上车辆，就用这个。

制作并不麻烦：后台点一次「**批量打印全部贴纸**」，所有车的贴纸排在一页里一次打完。
车牌、号码随时能改，改完不用重新打印。

### 车牌是结构化输入的

省份和发牌机关字母是固定集合，所以做成了下拉（字母里没有 `I` 和 `O` —— 跟 `1`、`0` 会看混），
后面的号码单独一格，凑齐后自动排版成 `浙G·5RT71`：

- **自动排版**：`浙` + `g` + `5rt71` → `浙G·5RT71`（转大写、补间隔点）
- **反向识别**：编辑已有车辆时，车牌会拆回三个控件预选好
- **粘贴也行**：直接粘 `京b 12345` 会被排版成 `京B·12345`
- **特殊车牌**：`使123456`、`领12345` 这类没有省份代号的，走「特殊车牌」那一栏原样保存
- 三段填全时以三段为准，原样栏只作为兜底

存储上仍然是**一个 `plate` 文本字段**，没有拆成三列 —— 这样扫码页、贴纸、搜索全都不用改，
也不会因为以后遇到 6 位新能源号牌（`京AD12345`）就得改表结构。

### 贴纸有三款尺寸

打印页上可以一键切换，`?size=square` / `?size=square6` / `?size=rect`：

| | 5×5 正方形 | 6×6 正方形 | 10×5 长方形 |
|---|---|---|---|
| 尺寸 | **50mm × 50mm** | **60mm × 60mm** | **100mm × 50mm** |
| 排版 | 标题在上、二维码居中、提示在下 | 标题在上、二维码居中、提示在下 | 二维码在左、文字在右 |
| 二维码 | **28.6mm**（框 34.5mm） | **33.6mm**（框 40.5mm） | **37.4mm**（框 45mm） |
| 标题 / 副标题 / 提示 | 11pt / 5.5pt / 6.5pt | 14pt / 8pt / 8pt | 19pt / 9pt / 9pt |
| 适合 | 后视镜旁、角落（省地方） | 想又大又清楚 | **既要大码又要大字的，选这个** |

三款都印同一套文案：「**扫码挪车**」/「**临时停靠 · 请多包涵**」/「**车辆挡路请扫码联系车主**」，
**不印车牌也不印编号**，所以贴纸可以随时撕下来贴到别的车上。

「框」是二维码 SVG 画布的外框，本体是真正的编码区（外面那圈是扫码必需的静默区，
按标准留 3 个模块，抹不掉）。表格里的**本体尺寸**才是决定「多远能扫到」的数字。

> **踩过的坑**：画布以前默认按「含静默区的正方形内接于圆」放大 √2 —— 那是给圆形轮廓留的余量。
> 结果 44mm 的框里二维码本体只有 **26mm**，四周一圈白边，白白扔掉 41% 的边长。
> 圆形轮廓方案已被否决（见下），这个余量也就没有存在理由，改成只有显式 `circular: true` 才留。
> e2e 里加了两条断言盯着它：本体必须占画布 ≥80%，且只有显式开启圆形裁剪时才出现 √2 余量。

尺寸是**实测出来的上限**，不是随手填的（用浏览器量真实渲染尺寸，再拿渲染出来的图跑 jsQR 解码）：

- 50mm 款可用高 46.5mm = 标题 4.5 + 副标题 2.2 + 二维码框 34.5 + 码上下留白 2 + 提示 2.9；
- 60mm 款可用高 55.5mm = 标题 5.7 + 副标题 3.3 + 二维码框 40.5 + 上下留白 2 + 提示 3.5。

**副标题要占整整一行高度，这个高度只能从二维码身上出**：正方形是竖排，多一行字就少一截码。
所以把副标题加回来时，二维码框相应从 37mm 收到 34.5mm（6×6 从 44 收到 40.5mm）——
换来的仍然是**比最初版本大 28% 的码**（最初 5×5 的框也是 38mm，但被 √2 余量吃掉后本体只有 22mm）。

> 长方形款是横排（码在左、字在右），副标题**不占二维码的高度**，还多出一点空间：
> 45mm 的框给出 **37.4mm** 的本体、19pt 标题和 9pt 提示。
> 想要「码最大 + 字最大 + 全三行文案」，长方形是唯一不用做取舍的那款；正方形是拿地方换方便。

### 打印页

打印页（单张 `/cars/<编号>/print`、`/codes/<编号>/print`，批量 `/print-all`、`/print-blank`）
把「A4 纸」直接画在屏幕上，所以**打印前就看得见会印成什么样**：

- **纸张预览**：屏幕上那张白纸就是 A4（210×297mm，四周 6mm 页边距，与 `@page margin` 一致），
  贴纸按真实毫米尺寸排在里面 —— 屏幕上每行几张，纸上就是几张。
- **同一套网格**：屏幕和打印**共用** `.sticker-sheet` 的宽度（198mm = A4 减左右各 6mm）和间距（5mm）。
  这条是关键：以前屏幕用 flex + `gap:6mm`、打印用 `inline-block` + `4mm` 外边距，
  两套算法算出的「每行几张」不一样，**预览等于在骗人**。e2e 有一条断言专门盯着它。
- **缩放提示**：页面顶部（在纸**上面**，不用滚过整张 A4 才看到）写着
  「打印时把缩放设成 100%（或实际大小）」—— 这是最容易踩的坑，缩放一变贴纸就不是实际尺寸了。
- 打印时工具栏、说明卡片、纸张轮廓全部隐藏（`@media print`），纸上只有贴纸；
  批量页每张贴纸**框外**另有一行小字（车牌或编号），纯粹给你对号用，裁剪时剪掉。

每行能放几张按 A4 可打印宽度算，页面上会直接写出来：

| 尺寸 | 每行 | 算式 |
|---|---|---|
| 5×5 方形 | **3 张** | 3×50 + 2×5 = 160mm ≤ 198mm（4 张要 215mm，放不下） |
| 6×6 方形 | **3 张** | 3×60 + 2×5 = 190mm ≤ 198mm |
| 10×5 长方形 | **1 张** | 2 张要 205mm，放不下 |

实测：5 张贴纸（3+2）打印或另存为 PDF 正好 **1 页 A4**。

### 贴纸编号：码与车解绑，绑定关系随时可改

**贴纸上印的是「编号」，不是车牌，也不是某辆车的记录号。** 编号先生成、后绑定：

```
生成一批空白编号  →  打印成贴纸（外观全通用，正面只有二维码）  →  谁拿到谁绑定
                                                              ↓
                    绑错了 / 换了车 / 撕下来贴到另一辆车上 → 改绑定就行，贴纸不用重印
```

对应的动作都在后台「贴纸编号」卡片里，全是纯 HTML 表单（禁用 JS 也能用）：

| 动作 | 说明 |
|---|---|
| **生成空白贴纸** | 一次生成 1~50 个编号；也可以先印一批囤着 |
| **绑定** | 把某个编号挂到自己的某辆车上；同一辆车可以挂多张贴纸（前后各一张） |
| **改绑** | 再绑一次就是改绑：编号不变，指向的车变了 |
| **解绑** | 摘下来变回空白贴纸，可以绑到别的车上 |
| **删除** | 这张贴纸作废（别人扫开就找不到了）。**车辆编号本身删不掉** —— 车还在它就永远有效 |
| **打印 / 批量打印空白** | 单张打印，或把所有待绑定编号排一页一次打完 |

**车主自己绑定的两种入口**：后台里选车牌直接绑；或者**用手机扫一下手里那张贴纸**，
扫开就是「这张贴纸还没绑定车辆」，登录后选中自己的车即可（这就是发贴纸给别人的用法）。

老贴纸完全兼容：早期版本印的是「车辆编号」，那种编号**不需要迁移也永远有效** ——
编号表里查不到时会回落到按车辆编号查（见 `src/app.js` 的 `resolveCode`）。
新建的车会自动带上自己的编号行，老车由启动时的迁移补齐（`scripts/migrate-legacy-codes.sql`）。

> **为什么不能「一个码贴所有车、还能自动认出是哪辆」？**
> 二维码里装的就是一个网址。A 车和 B 车贴同一个码，服务器收到的请求一模一样，
> 物理上就无法区分 —— 这不是实现问题，是二维码本身的性质。
> 所以行业里的做法都是「**版式通用 + 一物一码 + 绑定关系可变**」：
> 贴纸正面长得一模一样（不印车牌），每张的编号不同，扫到的是哪辆车由绑定关系决定。
> 行业调研见文末「同类产品是怎么做的」。

后台每辆车下方都有一条**管理链接**（`域名/edit/<编号>.<签名>`）。把它发给开这辆车的人：

- 对方打开就能改车牌、号码、启用/停用，也能自己打印贴纸；
- **只能改这一辆车** —— 看不到你的其他车辆，也拿不到后台总密码；
- 链接带 HMAC 签名，不可伪造、不可枚举；
- 换掉 `SESSION_SECRET` 会让所有管理链接立刻失效（等于一键收回全部授权）。

> 转发这条链接 = 交出这一辆车的修改权，请只发给你信任的人。

**通用码**（`域名/m`）—— 一个码贴所有车。但它里面没有车辆编号，所以启用了多辆车时，
扫码页会先列出车牌让扫码人点一下「是这辆」；只启用一辆车时则直接进那一辆。
它的用处是「先印一批一样的备用」，代价是扫码时多一步选择，而且所有车牌会对扫码人可见。

### 同类产品是怎么做的（调研结论）

查了实体挪车贴、草料二维码这类生码平台、以及同技术栈的开源同类项目，结论是：
**没有人真的「印一批一模一样的码贴所有车」**。「通用」是分两层做的：

| 模型 | 谁在用 | 扫码之后 | 硬伤 |
|---|---|---|---|
| **一物一码 + 绑定可改** | 主流实体挪车贴、本产品 | 码里是贴纸编号 → 查绑定关系 → 找到车 | 无（这就是本产品的模型） |
| **活码**（内容可改、码不重印） | [草料二维码](https://cli.im/help/quick-start/bulk-template-dynamic-qr-code) 等生码平台 | 一行数据一个码，各码有自己的编号与字段 | 是通用生码能力，不是挪车业务 |
| **账号级通用码** | 同一车主多辆车 | 扫码人从车牌列表里选（本产品的 `/m`） | 陌生人场景会选错，还暴露车主有几辆车 |
| **公共入口 + 车牌当钥匙** | 交管 12123「一键挪车」 | 输入车牌 → 按车牌找车主 | 要「车牌→车主」的公共库，私人产品做不了 |

要点：

- 实体贴纸的行业做法是**收到贴纸先绑定车牌**，并且**可以改绑**（换车不用重印）；
  通知走**虚拟号**，双方号码互不可见。参见[某挪车贴的官方帮助页](http://m.114piaowu.com/help/3117.html)。
- 同技术栈的开源同类（Cloudflare Worker + D1，与本项目几乎一样）：
  [oozzbb/car-qrcode-notify](https://github.com/oozzbb/car-qrcode-notify) ——
  「部署一次可多辆车使用」，每车一个编号。它的通知渠道比我们多
  （WxPusher / Bark / 飞书 / 钉钉 / QQ），**推送**这块值得抄：
  很多扫码人不愿意打电话，但愿意点一下「通知车主」。
- 交警免费发挪车码这种**批量发放**场景（[示例](https://www.thepaper.cn/newsDetail_forward_22156757)），
  只有「一物一码 + 后绑定」才做得成 —— 发的时候根本不知道码会贴到哪辆车上。
  这是本次改动的主要动机。

本产品与主流的已知差距（按性价比排序）：

1. ~~码与车绑定不可改~~ → **本次已补齐**（贴纸编号表 + 绑定/改绑/解绑）；
2. **没有推送通知**：只能打电话。加 WxPusher / Bark 这类 Webhook 成本很低；
3. **没有虚拟号**：现在靠车主自己填一个号码（可能本身就是隐私号），
   主流是平台下发 AXB 虚拟号。这条要接服务商、有资质和按分钟计费，免费版 Worker 也跑不动。

## 账号体系（每个车主一个账号）

- **车主**：`/signup` 用手机号或邮箱注册，登录后进 `/me`，**只能看到和管理自己的车**。
- **平台方**：`/login` 里账号留空、填后台密码，进 `/admin`，能看到所有车和全部车主账号。

权限在每个车辆接口上按归属校验：**别人的车一律按 404 处理**（连"存不存在"都不告诉你），
二维码、打印页、拨号记录全都一样。平台方「新增车辆」建出来的是**平台自有车**（`owner_id` 为空），
通用码只认这些车 —— 多租户下车主的车牌绝不会出现在通用码里。

数据隔离是在 SQL 层做的（`listCarsByOwner / listMessagesByOwner / markRead(ownerId)`），
不是取出来再过滤，避免漏掉某处。

## 一、部署到 Cloudflare Workers

需要 Node ≥ 22.13（只为跑 wrangler，Worker 运行时本身不依赖 Node）。Wrangler 用 `npx` 拉取，项目依然零依赖。

```bash
# 1. 建 D1 数据库，把输出的 database_id 粘到 wrangler.toml 的 [[d1_databases]] 里
npx wrangler d1 create chezai-qrcode

# 2. 建表（远程）
npx wrangler d1 execute chezai-qrcode --remote --file=./schema.sql

# 3. 设置两个密钥
npx wrangler secret put ADMIN_PASSWORD     # 后台登录密码
npx wrangler secret put SESSION_SECRET     # 随便一串长随机字符串

# 4. 部署
npx wrangler deploy
```

部署完会得到 `https://chezai-qrcode.<你的账号>.workers.dev`。

**第 5 步（重要）**：把这个域名填进 `wrangler.toml` 的 `PUBLIC_BASE_URL`，再 `npx wrangler deploy` 一次。

```toml
[vars]
PUBLIC_BASE_URL = "https://chezai-qrcode.<你的账号>.workers.dev"
```

不填也能用，但二维码会按访问时的 Host 动态生成——**以后换了域名，已经打印出去的贴纸全部失效**。
建议顺便绑一个自己的域名（Workers 支持自定义域，自带 HTTPS）。

然后打开 `https://<你的域名>/admin`，用 `ADMIN_PASSWORD` 登录，点「新增车辆」。

### 加表不用先跑迁移

`codes` 表（贴纸编号）由 Worker 在冷启动时自己补：

```sql
CREATE TABLE IF NOT EXISTS codes (...);
```

这样「加一张表」不需要「先跑迁移再部署」——否则中间那段时间线上每个请求都会
因为查不存在的表而 500。表结构仍以 `schema.sql` 为准，这里只是保证它一定存在。

历史车辆（早期版本的编号就是车辆编号）想出现在后台编号列表里，跑一次这个即可（幂等，可重复执行）：

```bash
npx wrangler d1 execute chezai-qrcode --remote --file=./scripts/migrate-legacy-codes.sql
```

> **不跑也不影响扫码**：编号表里查不到时会回落到按车辆编号查，
> 已经印出去的老贴纸永远有效。Node 版启动时会自动执行同一句。

**如果 `npx` 卡住不动**（某些网络环境下 `npx wrangler@4` 会一直没输出），
装到本地直接用，绕开 npx 的解析：

```bash
npm i --no-save wrangler@4        # 不写进 package.json
node node_modules/wrangler/bin/wrangler.js deploy
node node_modules/wrangler/bin/wrangler.js d1 execute chezai-qrcode --remote --file=./schema.sql
```

### Workers 上的几个细节

- **管理密码不存在数据库里**。Node 版会把密码 hash 后存库；Worker 版直接比对平台 secret，
  因为 secret 本来就不落库，没有可离线爆破的哈希。防的是在线猜测，由登录限流负责
  （同一 IP 10 分钟 10 次）。这也是为什么 Worker 版不需要 PBKDF2 —— 顺带避开了免费计划
  那 10ms CPU 限额的坑。
- **静态资源**（`public/`）由 Cloudflare 边缘托管，配置在 `wrangler.toml` 的 `[assets]`。
  显式给了 `binding = "ASSETS"`，Worker 先跑、未命中路由再转交，行为不依赖平台默认值。
- **会话密钥**没配 `SESSION_SECRET` 时会自动生成并存进 D1 的 `settings` 表。
  多实例部署请务必显式配置，别依赖自动生成。
- **限流**：拨号打点按 `messages` 表统计，登录按 `rate_limits` 表。
  D1 没有跨语句事务，所以登录限流是「读-写」两步，理论上并发时能多放过去几次——
  对这个场景可以接受（密码本身是高熵 secret，不是靠限流兜底）。

### 部署后打不开？先看这三条

部署完发现「调用次数 0、页面打不开」，按顺序排这三件事，能覆盖绝大多数情况：

1. **没有任何 URL** —— Cloudflare 上新建的 Worker，`workers.dev` 路由默认可能是关的。
   Worker → 设置 → 域和路由 → 启用 `workers.dev`（或者绑一个自定义域名）。
   入口没开的话，访问量永远是 0，也不会有任何日志。
2. **`database_id` 还是占位字符串** —— 打开 `/` 或 `/admin` 直接 500，多半是这个。
   注意 `wrangler deploy --dry-run` **不会**因此报错（它只做本地打包），
   所以「部署成功但一访问就报错」比「部署失败」更常见。先 `wrangler d1 create` 再部署。
3. **没设 `ADMIN_PASSWORD` secret** —— 后台登录页会明确提示「尚未配置管理密码」。
   设完 secret 需要重新部署一次才会生效。

另外建议顺手把 Observability 里的 **Workers Logs 打开**（默认可能是禁用的），
否则线上出问题只能靠猜；打开后用 `npx wrangler tail` 或面板都能看到真实的报错。

## 三、自检与测试

```bash
npm test        # 二维码编码器自检（快，纯计算）
npm run e2e     # 端到端：真的起服务，跑完整个流程（约 3 秒）
npm run verify  # 上面两个一起跑

# 补充：真实浏览器走一遍用户流程（可选，需要 playwright-core + 本机 Chrome）
PLAYWRIGHT_PATH=<...>/node_modules/playwright-core node scripts/ux-journey.js
```

**`npm test`** 做三类**有真实判据**的检查：

1. **对齐规范常量** — 纠错等级 M 在版本 1–10 的 byte 容量表、8 个格式信息串（ISO/IEC 18004 Table C.1）、版本信息串（Table D.1）
2. **Reed-Solomon 数学性质** — 生成码字代入 α⁰…α^(t-1) 的伴随式必须全为 0（解码器第一步就是这个）
3. **矩阵结构** — 尺寸、三个定位图形、定时图形、固定黑点，以及两份格式信息互相一致且等于按掩码算出的值

最后打印一个真实二维码的**字符画**，直接拿手机扫一下即可确认。

**`npm run e2e`** 在临时端口上拉起 Node 版服务（用临时数据目录，不碰 `data/`），
共 50 项断言，跑完自动关服务、清临时目录。其中几条是**安全与回归不变量**，改代码时最该盯住：

- 扫码页**绝不能**出现车主真实手机号（有独立拨号号码时）
- **没填「拨号号码」但填了手机号时，扫码页必须仍然有拨号按钮**（否则贴纸等于废纸）
- 两个号码都没填时，不能出现 `tel:` 按钮
- 会话 Cookie 必须是 HttpOnly，且 http 下不能带 Secure（否则本地直接登不进去）
- 未登录的写操作必须被拒

## 四、代码结构

```
src/core.js      共享：纯函数 + WebCrypto（随机、HMAC 签名 Cookie、时间、转义）—— 无任何 node: 依赖
src/qr.js        共享：二维码编码器（byte 模式 / 纠错 M / 版本 1-10）→ SVG
src/views.js     共享：所有页面模板
src/app.js       共享：路由 + 业务逻辑，输入请求描述、输出 { status, headers, body }
src/db.js        Node：node:sqlite 实现 store 接口
src/util.js      Node：读请求体、scrypt 口令、转发头
src/server.js    Node：http 适配 + 启动
src/d1.js        Workers：D1 实现 store 接口
src/worker.js    Workers：fetch 适配
schema.sql       两边共用的一份建表 SQL（纯 DDL，无 PRAGMA）
public/          style.css / app.js，两个平台各自托管
scripts/         start.js（Node 启动）、selftest.js（编码器自检）、e2e.js（端到端）
```

分层的关键是两道接缝：

- **请求/响应是普通对象**。`src/app.js` 只认识 `{method, pathname, url, cookie, ip, origin, readText}`，
  返回 `{status, headers, body}`。Node 适配层把它变成 `http.ServerResponse`，Worker 适配层变成 `Response`。
  （没有 `userAgent` —— 应用层根本不看 UA，也就无从记录。）
- **store 是纯异步接口**。`getCar / addCallLog / listMessages / bumpRateLimit …` 两边签名一致，
  所以共享层 `await` 谁都不知道自己跑在哪。

Node 的 `node:sqlite` 其实是同步的，这里刻意包成 async —— 为了和 D1 对齐，代价是零。

### 界面约定（改动前先看这几条）

- **不引 Google Fonts**：用系统字体栈（`system-ui` / PingFang SC / 微软雅黑）。
  大陆访问不到 Google Fonts，引了会拖慢首屏，甚至字体一直不加载。
- **图标一律内联 SVG，不用 emoji 或字体符号**：`☎` 这类字形在不同系统里长得完全不一样，
  也没法跟随文字颜色和粗细。装饰性图标要 `aria-hidden="true"`。
- **颜色只走 `:root` 里的语义变量**，深色模式单独给一套取值，不在组件里写死 hex。
- **间距用 `--sp-*`**（4 的倍数），别随手写 13px / 18px。
- **触控**：`touch-action: manipulation` 去掉移动端 300ms 点击延迟；
  可点区域不小于 `--tap-min`（44px）；扫码页底部留 `safe-area-inset`。
- **键盘焦点必须可见**（`:focus-visible`），错误提示带 `role="alert"`，
  并且尊重系统的 `prefers-reduced-motion`。
- **改动不整页刷新**：后台的表单带 `data-remote`，前端用 `fetch` 提交，
  服务端只回需要替换的片段（`{html: {id: innerHTML}}`），页面不重载 ——
  所以编辑面板不会每次保存都被收起、滚动位置也不会丢。
  没有 JS 时这些表单照旧整页提交，服务端两条路都支持。
- **改动必须当场有反馈**：因为不重载页面，光更新页面顶部的提示区是不够的 ——
  用户可能正滚在页面下方改一辆车，那行提示在他视野之外。
  所以每次改动还会弹一个**固定在屏幕底部**的轻提示（`role="status"`），
  不管滚到哪儿都看得到。

这几条在 `npm run e2e` 里有对应的断言，改坏了会被拦下来。

### 为什么还另有一个「真浏览器」脚本

`npm run e2e` 用的是 HTTP 断言：快、稳、每次都能跑，但它**看不到用户实际看到的东西**。
下面这些问题它一个都抓不到，全是真浏览器跑出来的：

| 真发生过的问题 | 为什么 e2e 抓不到 |
| --- | --- |
| 浏览器 `fetch` 发的是 `multipart/form-data`，服务端只认 urlencoded → **提交上去全是空字段，保存一次就把车牌号码清空** | e2e 自己发的是 urlencoded，永远对得上 |
| 提示条存在，但在页面顶部，用户正在下方编辑 → 他以为没保存 | 断言只检查「响应里有提示文案」 |
| 窄屏上「启用中」标签被挤成一列一个字 | 断言不看布局 |

所以：**`npm run e2e` 每次都要跑；改动界面之后，再跑一次 `scripts/ux-journey.js` 并看截图。**

## 五、隐私设计

扫码页上只有一个「一键拨号」按钮，**不提供留言**，页面本身不展示任何号码（号码只在 `tel:` 链接里）。

**不采集任何扫码人信息。** 具体地说，扫码人的 IP、UA、设备、位置、停留时间一概不落库 ——
拨号记录表里连 `ip` / `ua` 这两列都没有，一行记录只有「哪辆车、什么时候、读没读」：

```sql
CREATE TABLE messages (          -- 表名是历史遗留，现在一行 = 一次拨号
  id, car_id, kind, reason, content, contact, created_at, read_at
);
```

连「谁点的」这件事本身都不记录，所以也不存在按 IP 限流 —— 拨号打点的限流放在进程内存里，
键是车辆编号而不是 IP（连处理扫码人 IP 这一步都省了）。

| 数据 | 存放位置 | 说明 |
| --- | --- | --- |
| 拨号号码 `call_number` | 数据库 | 只出现在 `tel:` 链接里。设计上填隐私号 / 虚拟号 |
| 真实手机号 `phone` | 数据库 | 平时不返回。**但拨号号码留空时会退化成拨打它**（见下） |
| 扫码人信息 | **不采集** | 不记 IP、不记 UA、不记设备 |
| 通话内容、拨出号码 | **不采集** | 只记「点了一次按钮」 |

> 平台层面另说：Cloudflare 自己会保留请求级日志与分析数据，这不是应用代码能控制的。
> 这个部署里 Workers Logs / Traces 都是关的；如果在意，别在面板里打开它们。

**关于两个号码的关系**（这一点容易被误解）：

- 填了「拨号号码」→ 扫码人拨打它，真实手机号不出现在页面里。想藏号就用隐私号服务。
- 没填「拨号号码」但填了「真实手机号」→ 扫码页拨打真实手机号（**等于公开它**）。
  没有隐私号服务、只想让人打给自己，就属于这种情况，按需选择。
- 两个都留空 → 扫码页没有按钮，贴纸等于没用。

其他措施：

- 车辆编号是 10 位随机码（去掉易混字符的 58 字符表，且做了拒绝采样避免取模偏差），不可枚举；后台可随时停用某个码
- 后台只记录「有人点了一次拨号」，**不记录通话内容，也不记录拨出号码**
- 拨号打点限流在内存里做（按车辆编号，10 分钟 30 次），不写库、不记 IP；只影响记录写入，不影响用户能不能拨出去
- 会话是 HMAC-SHA256 签名的 HttpOnly Cookie，`SameSite=Lax`（跨站 POST 不带 Cookie，等于自带 CSRF 防护），12 小时过期
- 全站 CSP `default-src 'none'`，所有输出经过 HTML 转义

> 唯一还会用到 IP 的地方是**后台登录限流**（`rate_limits` 表，10 分钟窗口）——
> 记的是车主你自己的 IP，用来防在线猜密码，扫码人的 IP 不经过这里。

## 六、接虚拟号码（隐私号）

现状：扫码页上的号码取自车辆资料的「**拨号号码**」字段。
**这意味着只要把虚拟号填进那个字段，L0 / L1 两条路都是零代码的** —— 代码不用改一行。

### 三条路的成本差 20 倍

| | L0 车主自备副号 | L1 平台代购固定号 | L2 号码池 + 按次绑定 |
|---|---|---|---|
| 谁掏钱 | 车主自己 | 平台 | 平台（摊薄） |
| 成本 | **和多号 5 元/月 ≈ 60 元/年** | 阿里云虚商号 **120 元/年**、运营商号 **180 元/年** | 号码池月租 ÷ 车主数 + 通话费 |
| 每车每年 | 60 元（车主付） | 120–180 元 | 可摊到 **几元** |
| 代码改动 | **无** | **无** | 需要写（约 200 行） |
| 扫码人体验 | 直接拨，无感 | 直接拨，无感 | **要多填一次自己的手机号** |

> 阿里云号码隐私保护实测报价（2026）：虚商号码首购 30 元、月租 10 元/月；
> 运营商号码首购 45 元、月租 15 元/月；通话 0.060 元/分钟；录音 0.010 元/分钟。
> 首购含前 3 个月月租。见[计费概述](https://help.aliyun.com/zh/pnp/product-overview/billing-overview)。
> 和多号：副号 5 元/月（或 36 元/年），通话走主号套餐。
> 见[和多号收费说明](https://hdh.10086.cn/mobile/help_center_4.jsp)。

### 商业上必须先想清楚的一件事

**「一车一个固定虚拟号」是亏的。** 平台代购要给每辆车每月掏 10–15 元，
一年 120–180 元 —— 收 19 元/年 的年费，一辆车亏 100 多。这条路只能卖给企业车队，不能做 C 端。

**要便宜就必须用号码池 + 按次绑定**：平台只买少量号码（比如 5 个），
谁被扫码就给谁临时绑一个，用完自动解绑、号码回收共用。
5 个运营商号码月租 75 元，服务 500 个车主，摊到每车每月 0.15 元。

**但代价是扫码人要多一步**：AXB 绑定必须知道「谁在打」（B 号码），
而我们的扫码页现在是「点一下直接拨」，压根不知道扫码人是谁。
所以 L2 要改成：点按钮 → 填一次手机号（或一键获取本机号）→ 平台回拨接通双方。

> 一句话取舍：**零摩擦 = 车主真实号曝光（或车主自备副号）；真隐私 = 扫码人要多填一次手机号。**

### 各家的门槛

- **阿里云 / 腾讯云 / 华为云**：都要**企业实名认证**才能开通号码隐私保护，
  还要先创建号码池、购买号码、提交使用场景审核。个人开发者基本开不了。
  四类号码：AXB（一对一）、AXN（一对多）、AXG（群组）、AXN 分机号；
  华为云文档提到 AXB/AXE 支持自动解绑，**AX 模式不支持自动解绑** —— 选型时要留意。
- **和多号（中国移动）**：这是**消费者业务，个人就能办**，5 元/月。
  它是「副号」，别人拨副号就打到你手机上，你的真实号不暴露。
  限制：只能移动用户办，副号是 12583/165 之类号段，短信能力有限。
  联通有「沃小号」、电信也有类似副号业务。

### 如果要做 L2，改动点是这些

1. 新增 `src/privacy-number.js`：一个 provider 适配层
   （阿里云 `BindAxb` / 腾讯云 `CreateAXBCall` 之类，签名与参数各家不同）
2. `handleScan`：L2 模式下不再直接给号码，改成给一个「获取通话」的按钮
3. 新增 `POST /c/:code/connect`：收扫码人手机号 → 调 `BindAxb(A=车主, B=扫码人, X=池中号码, 过期=1 小时)`
   → 返回 X 号码给页面跳 `tel:`，或直接发起回拨
4. 接服务商的**通话状态回调**：解绑号码、回收池、写通话记录
5. 号码池的分配/回收/计费，以及「同一个 B 频繁拨打」的防骚扰

只有在你要把它当付费功能卖的时候才值得做这一步。想先验证需求，
**先用 L0**：让车主自己去办一个副号，填进「拨号号码」，今天就有效果。

两个平台共用这份逻辑，所以只改一遍。数据层不用动。

## 七、已知边界

- **`*.workers.dev` 在中国大陆打不开**（这是本项目最需要注意的一条）。实测：域名被 DNS 污染，
  且 TLS 握手阶段就会被重置（SNI 阻断），换任何 DNS 都没用。如果扫码的人和车主在中国大陆，
  **必须给 Worker 绑一个自己的域名**（自定义域名的 SNI 不在拦截名单里，Cloudflare 的 IP 本身是通的），
  或者干脆用 Node 版部署在国内服务器上。仅靠 `workers.dev` 的部署只适合境外用户
- **URL 上限 213 字节**（版本 10 / 纠错 M）。域名太长或带一堆参数就会超，超了在生成二维码时明确报错，不会静默截断
- **拨号是 `tel:` 跳转**，扫码人手机上是否弹拨号盘取决于系统与浏览器（微信内置一般能唤起；被拦截时可长按复制号码，但页面本身不展示号码，所以更稳的做法是提示用户用系统相机扫码）
- **D1 没有跨语句事务**，登录限流是读-写两步（见上文）
- **Workers 免费计划的 CPU 限额较低**。这里每个请求只做几次 D1 查询加一次二维码矩阵运算，
  并且二维码结果按「域名+编号」缓存在 isolate 内，正常规模没问题；车辆特别多（后台一页几十张二维码）时才需要留意
- **单租户时代已过去，现在是多租户**：一个部署服务多个车主。平台方的车（`owner_id` 为空）
  和车主的车是分开的，通用码、批量打印、拨号记录都按身份过滤
- **注册是开放的**：任何人拿到域名都能注册。要控制成本或做成邀请制，
  在 `/signup` 处理器前面加一道白名单即可（正路是接短信验证码）
- **建车要有「身份」**：车牌、真实号、拨号码至少填一个，否则拒绝创建。
  这条不是洁癖：空记录堆起来之后，通用码会把一堆「未填写车牌」列给扫码人看。
  平台后台对历史空记录提供了「一键清理空白车辆」
- **密码哈希用的是 PBKDF2（50,000 次迭代）**：Cloudflare Workers 免费版每次请求只有 10ms CPU，
  这个值是按「免费版能跑」实测调出来的。安全上更稳的做法是升级 Workers Paid 后把
  `PBKDF2_ITERATIONS` 调高（OWASP 建议 600,000）。迭代次数写在哈希串里，
  **调高不影响已注册的账号**，老哈希仍按各自的次数校验
- **平台后台只有一个密码**，没有二次验证。它是最高权限（能看到所有车主），
  泄露的后果比单个车主账号严重，建议用长随机串并定期更换
- **`cloudflareinsights.com` 的脚本会被 CSP 拦掉**：Cloudflare 对放在它上面的域名
  默认开启 Web Analytics，会往 HTML 里注入 `beacon.min.js`；而本站 CSP 是
  `default-src 'none'`，所以它会加载失败并在控制台留一条报错。
  想彻底消掉：Cloudflare 面板 → 该域名 → 概览/分析 → 关闭 Web Analytics。
  想让它工作（会统计扫码页访问，与「不采集扫码人信息」的承诺有冲突）：
  在 `src/app.js` 的 `SECURITY_HEADERS` 里把 `script-src` 加上
  `https://static.cloudflareinsights.com`，`connect-src` 加上 `https://cloudflareinsights.com`。
- **移动端约定**：断点按内容取 640 / 1024；手机上小按钮自动提到 44px；
  顶部栏和容器让开 `env(safe-area-inset-*)`（`viewport-fit=cover` 会让内容顶到刘海下）；
  手机上先显示「车辆与贴纸」再显示「新增车辆」那个长表单（`body.admin .wrap` 的 `order`）。
- **单租户**。一个部署 = 一个车主后台。要做成 SaaS 多租户得再加账号体系与行级隔离

### 后台页面的布局约定（改前实测 8.8 屏 → 现在 4.3 屏）

后台是**会一直变长**的页面：车辆会加、拨号记录只增不减。所以布局必须当成
「长了以后还站得住」来设计，而不是「现在数据少所以看着挺好」：

- **列表必须有上限**：`recordListHtml()` 默认只铺最近 10 条，更早的塞进一个
  `<details>`（纯 HTML，禁用 JS 也能展开）。以前全铺，20 条记录就占 5.4 屏。
- **一行一条，不重复**：每条记录原来印三行字，其中两行（「有人点了一次拨号」、
  「不记录任何扫码人信息」）**每条都一样**。这种「每行都重复的说明」是纯噪音，
  现在只在卡片标题下面写一次。记录行因此从 92px 降到 58px。
- **时间不带年份**：列表里显示 `09-21 02:19`。375px 手机上，带年份的时间加按钮要 340px，
  一行只有 309px —— 必折行。**为了塞进一行而砍掉的信息，优先砍年份这种没人看的**。
- **长说明收进 `<details class="card-help">`**：默认页面上只留一句关键的，
  想看「贴纸怎么用 / 这个码认哪些车 / 管理链接是什么」再点开。
- **车卡在桌面端分栏要用 `auto-fit` 而不是 `auto-fill`**：`auto-fill` 会保留空轨道，
  于是只有一辆车的用户对着半宽卡片 + 半边空白；`auto-fit` 让空轨道塌缩，单车铺满、多车才分栏。
- **首页（`/`）永远是登录页或后台，不是扫码页**：扫码入口是 `/m` 和 `/c/<编号>`。

> **验证上的坑**：这个站的 CSP 是 `default-src 'none'`，**连内联 `<style>` 一起挡**。
> 所以「往页面里注入一段 CSS 再量尺寸」的测法是量不出东西的（注入的规则根本不生效，
> 所有方案量出来数字都一样）。要测样式变体，得用 Playwright 的 `page.route`
> **替换 `/style.css` 的响应内容**，或者直接改文件后重新量。
